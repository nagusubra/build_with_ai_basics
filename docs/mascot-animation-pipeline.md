# Mascot animation pipeline: from-scratch, piece-by-piece AI assets to Rive

This is the full recipe used to build BakeOut's mascot animations: first the **DuoWelcome** proof
(`app/tool/mascot_rive_duo/`), then the **Jack wingman** rig (`app/tool/mascot_rive_jack/`). It covers the
tech stack, tool setup, the image-model workflow, the rig and animation code, verification and Flutter
integration, so you can make a new character or a new move on your own.

> **Start here:** the [animation workshop README](../app/tool/README.md) contains
> the isolation audit, editor portability, limitations and completion gates.
> Use the [starter prompt](mascot-animation-starter-prompt.md) in a new session.
> **Animation-only is the default; app deployment is separately approved.**
> Follow the checklist in
> [new-mascot-animation-playbook.md](new-mascot-animation-playbook.md). AI agents can load the
> `mascot-animation` skill (`.agents/skills/mascot-animation/SKILL.md`), which wraps the same steps.

## 1. Why piece by piece

Animating one finished picture means cutting it up after the fact. Hidden areas (behind an arm, under a
hat) don't exist, and every warp stretches painted pixels. That looks jarring. Instead:

1. Generate one **master pose** with an image model, on a flat chroma-green background.
2. Ask the model for **edits of that same image**: the body without a head, each arm pose, each facial
   expression, each prop. Every edit says "keep everything else pixel-identical".
3. Key the green out and **register** every render back onto the master (same scale and position), so
   parts stack with zero hand alignment.
4. Rig the parts in Rive as a hierarchy of pivoted nodes, then animate them with code-generated timelines:
   squash and stretch, head bob, follow-through, blinks, pose swaps hidden in anticipation.
5. Render real frames with the Rive CLI, look at them, fix, repeat.

You get full control. Every part is a separate transparent layer with a known pivot, and you can rebuild
any part by regenerating one image.

## 2. Tech stack

| Layer | Tool | Notes |
|---|---|---|
| Image model | **Gemini** (gemini.google.com, "Create image"), ChatGPT image gen as fallback | Best at "edit this exact image, change only X" |
| Browser automation | **Playwright MCP** server + **Playwright MCP Bridge** Chrome extension | Drives your real logged-in Chrome tab, so no API keys |
| Agent | Cursor, OpenCode, Copilot or another write-capable agent | Original run used VS Code; shared skill/docs work without its chat history |
| Image processing | Python 3.12, **NumPy**, **Pillow** | Chroma key, unmixing, registration (NCC), masks, warps |
| Animation format | **Rive** `.riv`, authored as **RML** (Rive Markup) XML | Generated by Python; no manual editor work |
| Build / render | **Rive CLI** (`~/.rive/bin/rive.exe`) | `--verify`, `--once` (build), `--screenshot` (real renders) |
| App runtime (integration only) | Flutter + `rive: 0.14.11` | Current manifest pin; `AnimatedMascot` in `app/lib/widgets/mascot_rive.dart` |
| Previews | Pillow WebP/GIF | Contact sheets and loop previews in `build/` |

## 3. One-time setup

### 3.1 Playwright MCP with your own Chrome

This is an optional, **VS Code-specific configuration example**, not a universal
MCP config. See the [portability guide](../app/tool/README.md#6-editor-portability-and-mcp)
for Cursor/OpenCode and manual generation. Record a tested package version rather
than leaving `@latest` for a reproducible setup.

1. Install the **Playwright MCP Bridge** extension in Chrome and open its options page. It shows a
   connection token.
2. Add an MCP server to VS Code (`.vscode/mcp.json` or user `mcp.json`). Keep the token in an env var or
   input; **never commit it**:

   ```jsonc
   {
     "servers": {
       "playwright": {
         "command": "npx",
         "args": ["@playwright/mcp@latest", "--extension"],
         "env": { "PLAYWRIGHT_MCP_EXTENSION_TOKEN": "${input:pwToken}" }
       }
     },
     "inputs": [{ "id": "pwToken", "type": "promptString", "description": "Playwright MCP extension token", "password": true }]
   }
   ```

3. Start the server, sign in to Gemini (and ChatGPT) in that Chrome profile, and leave a Gemini tab open.
   Rotate the token if it was ever pasted anywhere shared.

## 4. Generating assets with Gemini

### 4.1 The automation loop (`app/tool/gemini_web/`)

Typing in the Gemini UI by hand works too. The scripts just make it repeatable and cheap:

The tool names and `filename` output parameters below describe the bridge used
originally. Discover the actual connected tool schemas; use manual upload/download
if the destination client cannot execute/save the helper results.

| Step | What runs |
|---|---|
| 1. Write the prompt | `Set-Content -Encoding utf8 prompt.txt "..."` |
| 2. Build the send script | `python app\tool\gemini_web\gen.py prompt.txt [image.png ...]` writes `send.js` and `fetch.js` next to itself. With images it opens a **new chat** and pastes them; without images it posts a **follow-up** in the current chat |
| 3. Send | MCP `browser_run_code_unsafe` with `filename = app\tool\gemini_web\send.js` |
| 4. Wait and fetch | MCP `browser_run_code_unsafe` with `filename = app\tool\gemini_web\fetch.js`. It polls up to 45 s for a new `model-response img` and stores it as a PNG data URL in `window.__out`. If `{ok:false}`, inspect page state before retrying; it may re-press Send |
| 5. Dump | MCP `browser_evaluate` with `function = () => window.__out` and `filename = dump.txt` |
| 6. Save | `python app\tool\gemini_web\grab.py dump.txt design\...\raw\name_v1.png`, which decodes the PNG and deletes the dump |

Then **look at the image** before using it.

Gotchas we hit:

- **The tab must be visible.** Gemini won't send from a hidden or minimised window. Both scripts call
  `page.bringToFront()` first; keep the Chrome window on screen.
- Images are attached by dispatching a synthetic `paste` with a `DataTransfer`. Text goes in with
  `execCommand('insertText')`, and the send uses a real Enter on the editor.
- Prompt files written by PowerShell have a BOM, so `gen.py` reads them as `utf-8-sig`.
- To start a **new chat without editing** an image (e.g. a prop), attach the master anyway as a *style
  reference*.
- **Credits:** each image costs a generation. Batch thinking, not generations: view every result and fix
  the prompt rather than rerolling blindly. Respect provider quotas; pause or ask for an approved
  alternative provider when limited. Do not cycle accounts to evade limits. The scripts target
  Gemini's DOM; on ChatGPT, drive it with plain MCP clicks and typing, or upload and download by hand.

### 4.2 Prompt rules that make parts line up

- Always end with: **"on a flat pure green background (#0CF50C), 1:1 square, no shadow."**
- For anything that must register: **attach the master and say "keep this exact image pixel-identical,
  only change X; do not move, resize or redraw anything else."**
- Make a **pose** first, then in the *same chat* ask for an **isolation** ("now keep only the arms, hand,
  pencil and pad exactly as drawn; everything else flat green"). Use the pose for colour and the isolation
  as the matte.
- Make **expressions** from the isolated head (`head_v1`), one per chat: "keep the head, hat, stem, size
  and position identical; only change the face to …".
- Ask for the master with **limbs clear of the body**, so arms can be cut and rotated without holes.
- Props (bulb) get their own image; small shapes like dots, rays, sparkles and ink lines are cheaper and
  crisper as Rive vector shapes.

The exact prompts and the part list for Jack are in
[`design/mascots/jack_rig/README.md`](../design/mascots/jack_rig/README.md).

## 5. Keying and registering (`app/tool/mascot_rive_jack/parts.py`)

- **Key:** alpha comes from greenness `g - max(r, b)` (opaque at ≤ 70, clear at ≥ 150). A 3 px
  open removes speckles. Soft edges are **unmixed** against the measured background colour:
  `fg = (c - (1 - a)·bg) / a`. Within 4 px of the silhouette, any green lead (≥ 40) is treated as
  background, which kills the green-lit rim Gemini paints around objects. Interior green details (apron
  cherry stems) are untouched, and real green parts (stem and leaf) opt out with `keep_green`. A final
  despill clamps G to `max(R, B)`.
- **Register:** `register()` finds `master = s·src + (dx, dy)` by normalised cross-correlation over a box:
  a coarse grid, then a 0.5 px refine. For Jack every pose came back at offset 0 (NCC 0.99) and every face
  matched `head_v1` (silhouette IoU 0.998). The head edits share one transform, `HEAD_T`.
- **Split:** where one render holds two parts (hat and stem; pencil arm and pad), cut with simple
  geometric masks (x thresholds, colour tests like "red sleeve"). Subtract the dilated head or hat alpha
  from parts that sit behind them.
- Keep `raw/` untouched. Everything downstream is reproducible from `build_jack.py`.

## 6. Rig and animation (`app/tool/mascot_rive_jack/build_jack.py`)

The builder runs: raw renders → keyed, registered parts (`design/mascots/jack_rig/parts/`,
`jack_rig.json`) → 0.75× runtime PNGs (`assets/`) → `scene.rml` → Rive CLI → `.riv`.

**Hierarchy** (first child draws on top). An FX node holds sparkles, thought dots and the bulb, with rays
and glow. The Jack root at the shoes holds the pencil arm, the slanted pad (with ink lines and a heart),
the think hand, the pad, the Head node at the neck (hat, stem, blink, faces), the raised idea arm (behind
the head) and the body. Every node's origin is its **pivot**, so rotations look anatomical.

**Motion vocabulary** (each is a small function you can reuse):

| Helper | Effect |
|---|---|
| `squash` | Root scaleX/Y anticipation → stretch → settle. **Pose swaps happen inside the squash** so they read as one motion |
| `pose_holds` | Hard opacity switches between pose layers (`POSES` lists what each pose shows) |
| `bob_head` | Head rotation and dy around the neck |
| `follow` | Hat and stem follow-through: the head rotation times a gain (−0.9, −2.4) |
| `blinks` | Fast blink overlay on the eyes only |
| `thought_dots`, `bulb_pop`, `bulb_steady` | Thinking bubbles; bulb overshoot pop with glow pulse and rays |
| `scribble` | Ink lines grow along the pad's slope, then a heart pops |
| `hops`, `sparkle_burst` | Happy bounce and twinkles |
| `wave` / `flow` | Idle sine motion. `flow` tracks get C1-continuous Bézier handles, including across the loop seam, so loops never hitch |

Rules baked into `keyed()`: every track starts at 0, ends at the loop length, and **frame 0 equals the
last frame** (it asserts this). So loops are seamless by construction.

**Artboards instead of inputs:** each segment is its own artboard with its own looping state machine.

| Artboard | Length | Contents |
|---|---|---|
| `JackWingman` | 480 f / 8 s | Full loop: think 0–126 → idea 126–216 → write 216–372 → smile 372–450 → back to think |
| `JackThink` | 150 f | Hand on chin, thought dots |
| `JackIdea` | 120 f | Bulb on, star eyes |
| `JackWrite` | 180 f | Scribbling, heart |
| `JackSmile` | 120 f | Hops and sparkles |

Any UI spot can pick a segment just by artboard name. For example: `JackThink` while a reply loads,
`JackIdea` on a suggestion chip, `JackWrite` while composing, `JackSmile` after sending.

**RML notes:** property keys are x = 13, y = 14, rotation = 15, scaleX = 16, scaleY = 17,
opacity = 18. Ids must be unique per artboard, so each artboard offsets them by a base (10000, 20000, …).
Images reference `ImageAsset`s by id. Put `LinearAnimation` before `StateMachine` inside the artboard.

## 7. Verify by looking (`verify_jack.py`)

```powershell
python app\tool\mascot_rive_jack\build_jack.py
python app\tool\mascot_rive_jack\verify_jack.py          # add --quick to skip the preview
```

It runs:

1. `rive <dir> --verify` (must be 0 errors and 0 warnings).
2. `--once` to build `build/jack_wingman.riv`.
3. **Real Rive screenshots** of the story beats with `--screenshot --advance=N+1`. The first advance only
   enters the state machine.
4. A loop-seam check (frame 0 vs frame 480 must match).
5. Captures of each segment artboard. It swaps `main:` in `rive.yaml`, because the CLI renders the main
   artboard only.

Outputs are `build/review.png` (contact sheet), `build/chat_size.png` (how it reads at 120 px) and
`build/preview.webp`/`.gif`. **Open them every iteration.** That's how the green rim, pose pops and
misplaced ink lines were caught.

PowerShell shows the CLI's stderr logging as a NativeCommandError; look for "0 errors" instead of the exit
colour, **and require a successful exit code**. Jack's verifier does not enforce the
file-size budget or each segment seam; its quick mode omits previews and the
small-size strip. See the workshop README for the full quality gate.

**Live preview in any browser (including VS Code's):** `.\app\tool\preview_mascot_jack.ps1` serves the
folder and opens `preview.html` (`-Artboard JackWrite` starts on a segment; `-Native` opens the Rive CLI
window instead). The page plays the real `.riv` with the Rive web runtime at full size and at the 120 px
chat size, with a button per artboard. The manual equivalent is:

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory app\tool\mascot_rive_jack
# open http://127.0.0.1:8765/preview.html
```

## 8. Flutter integration

**Optional, separately approved deployment step.** Standalone animation tasks stop
before this section and do not change Flutter or shipped assets. New artboards
are not automatically discovered by the app.

1. Copy the build into the app's Rive assets (the folder is already in `pubspec.yaml`):

   ```powershell
   Copy-Item app\tool\mascot_rive_jack\build\jack_wingman.riv app\assets\mascots\rive\jack_wingman.riv
   ```

2. Add poses to the `MascotPose` enum in `app/lib/widgets/mascot.dart`. The first value is the PNG
   fallback; the second is the artboard:

   ```dart
   boyWingman('cherry_boy_planning', 'JackWingman'),
   boyThink('cherry_boy_planning', 'JackThink'),
   ```

3. Render with the asset. `AnimatedMascot` falls back to the PNG on web, with Reduce Motion or on Rive
   failure:

   ```dart
   AnimatedMascot(MascotPose.boyWingman, size: 120, animationAsset: 'assets/mascots/rive/jack_wingman.riv')
   ```

   `AnimatedMascot` needs one Rive file loader per asset (`MascotMotion.loaderFor(asset)`) to play anything
   other than `cherry_mascots.riv`.

For a guy's profile, show `JackWingman` in the chat header. Use the segment artboards wherever a single
beat fits.

## 9. Make a new move or character

1. Generate or reuse the master. Add `raw/` edits for the new pose or expression with the prompt rules
   above. View each one.
2. Add the part to `build_parts()` and `LAYERS`, add pivots, and add it to `POSES` if it's a pose.
3. Write a `timeline_*` from the helpers, then add an `ARTBOARDS` entry.
4. Run build and verify. Look at `review.png` and `preview.webp`. Iterate on timing (anticipation →
   action → overshoot → settle) before adding more art.
5. Deliver the reviewed `.riv` in the workshop. Only copy it into the app and wire
   the artboard after explicit integration approval.
