# Playbook: make a new mascot animation

This is a checklist for building a new animation the way Jack's wingman loop was built: every piece is
generated by an image model, registered onto one master, then rigged and animated in code. The reasoning
and tool setup are in [mascot-animation-pipeline.md](mascot-animation-pipeline.md); this page is the
"do this, then this" version. Budget about 10–20 image generations and an afternoon.

Reference implementation: [`app/tool/mascot_rive_jack/`](../app/tool/mascot_rive_jack/README.md) +
[`design/mascots/jack_rig/`](../design/mascots/jack_rig/README.md).

**Start with the [workshop README](../app/tool/README.md)** for the isolation audit,
tool capabilities and cross-editor setup. Use the
[starter prompt](mascot-animation-starter-prompt.md) in a fresh agent session.
Default to **animation-only**: no Flutter code, shipped assets, tests or pubspec
changes. Integration is an optional, separately approved task.

---

## Step 0: Set up (once per machine)

- [ ] Check Git status, permissions and tool versions. Prefer a separate worktree for concurrent app work.
- [ ] Python 3.12 + NumPy/Pillow. Check imports first; install missing dependencies into your local environment.
- [ ] Rive CLI at `%USERPROFILE%\.rive\bin\rive.exe` or on PATH. Check version/help.
- [ ] Optional: Chrome with the **Playwright MCP Bridge** extension. Add the VS Code MCP server
      `npx @playwright/mcp@latest --extension` with `PLAYWRIGHT_MCP_EXTENSION_TOKEN` passed as an input
      (section 3 of the pipeline doc).
- [ ] For new art only: signed in to an approved image provider. Respect quotas; pause or ask for an approved alternative when limited.
- [ ] Confirm image viewing and actual build execution are available. Read-only agents can review, not finish the animation.

## Step 1: Storyboard before generating anything

Write this down in the rig README first and obtain approval, including a generation
budget. It decides every asset you'll need. Skip generation when existing art suffices.

| Question | Jack wingman example |
|---|---|
| Where does it play, and at what size? | Chat header, 120 px, light background |
| Length and loop? | 8 s seamless loop; segments reusable on their own |
| Beats (story)? | think → idea pops → writes it → smiles → repeat |
| Poses (arm/body changes) per beat? | think (finger on chin), idea (finger up), write (pencil + pad) |
| Expressions per beat? | think "hmm", star-eyed idea, tongue-out concentration, happy closed-eye smile, blink |
| Props? | bulb (image); thought dots, rays, sparkles, ink lines, heart (vector) |
| What moves continuously? | head bob, hat/stem follow-through, breathing, blinks |

**Rule of thumb:** a pose is a new image, an expression is a new image, and anything small and geometric
is a Rive shape. Keep pose count low (2–4); expressions are cheap.

## Step 2: Make the master

Create `design/mascots/<rig>/raw/` and generate **one** master:

> Recreate this exact character as a clean character-sheet master: front facing, standing, arms relaxed
> slightly away from the body so the hands don't overlap it, neutral closed smile, same outfit and
> render style. Centered, full body, filling ~85% of the height, on a flat pure green background
> (#0CF50C), 1:1 square, no shadow.

- [ ] Attach your best existing art of the character as the reference.
- [ ] Check: limbs clear of the body, nothing cropped, background flat green, style on brand.
- [ ] Save as `raw/master_v1.png` and copy to `<rig>/master.png`. **Every later edit attaches this file.**

## Step 3: Split it into parts (each in a new chat, attaching the master)

| Part | Prompt core ("Keep this exact image pixel-identical… only …") |
|---|---|
| Body | "…remove the head, hat and stem entirely; keep body, outfit, legs and shoes exactly where they are…" |
| Head | "…keep only the head (with hat/hair/stem); remove the body…" |
| Accessories that should sway | "…keep only the hat and the stem with its leaf…" |
| Each pose | "…keep head, legs, feet, camera and scale identical. Only change the arms: …" |
| Arms matte for a pose | Same chat as the pose: "Now keep only the arms, hands and held props exactly as drawn; everything else flat green." |
| Each expression | Attach `raw/head_v1.png`: "Keep this exact head, hat, size and position identical. Only change the face to …" |
| Blink | From the head: "…only close the eyes into soft curved lashes with a gentle smile…" |
| Prop | Attach the master as a *style reference*: "In the exact same render style, create a SEPARATE prop image: …" |

Every prompt ends with **"on a flat pure green background (#0CF50C), 1:1 square, no shadow."**

Per image:

- [ ] Run it with the [`gemini_web`](../app/tool/gemini_web/README.md) loop, or by hand in Gemini.
- [ ] **Open the result and look.** Is anything moved, resized, restyled or cropped? Then re-prompt with the specific
      complaint in the same chat; don't reroll blindly.
- [ ] Save as `raw/<part>_v1.png` (bump `_v2` instead of overwriting).
- [ ] Write the prompt into the rig README.

## Step 4: Key, register and cut parts

Adapt `app/tool/mascot_rive_jack/` into a unique workshop (`parts.py` is reusable;
the builder/verifier are character-specific). Do not blindly copy generated
outputs. Update all paths/output names/preview settings to avoid writing into Jack.

- [ ] Update constants: `RIG`, `CROP` (the master-space window to show), `S` (runtime scale), and pivots.
      Measure pivots on `master.png`: neck under the chin, shoulders, hat band, root between the feet.
- [ ] In `build_parts()`: `key()` every render (pass `keep_green` for genuinely green parts) and
      `register()` anything that may have shifted. Gemini usually returns offset 0; check the NCC is above 0.95.
- [ ] Cut combined renders with simple masks (x/y thresholds, colour tests), subtract dilated head/hat
      alpha from parts that sit behind them, and cut the body under the head.
- [ ] Run the builder and open `design/mascots/<rig>/parts/*.png` on dark **and** light backgrounds. Look for
      green rims, holes and leftover background.

## Step 5: Rig

- [ ] List `LAYERS` (draw order) and the node hierarchy in `rig_xml()`: FX on top, then arms in front of
      the body, the head node at the neck pivot (hat, stem, blink, faces inside), arms behind the head, then the body.
- [ ] Put every node's origin at its pivot. Images are offset inside nodes, so rotations look natural.
- [ ] Fill in `POSES`: which layers are visible in each pose.

## Step 6: Animate

Write one `timeline_<name>()` per artboard using the helpers, and add it to `ARTBOARDS` (unique base id
per artboard, step 10000).

**Timing cheat sheet at 60 fps:**

| Motion | Frames | Notes |
|---|---|---|
| Blink | 8–10 (close 3, hold 2, open 4) | Every 2–4 s, never perfectly regular |
| Pose swap | Anticipation squash 8–10 → swap on the squash frame → stretch 6–8 → settle 12–20 | Hard opacity swap, hidden in the squash |
| Head bob / tilt | 0.03–0.06 rad, 30–60 frame periods | Lead with the body, head follows 2–4 frames later |
| Follow-through | Hat −0.9×, stem/leaf −2.4× head rotation | Gives bounce for free |
| Prop pop | Scale 0 → 1.15 → 0.95 → 1 over ~20 frames, `back` ease | Add glow or rays a few frames after |
| Hops | 18–24 frames each, squash on landing | Two hops read as "happy" |
| Idle | `wave()` sine on hands and pads, 0.01–0.03 rad | Keeps holds alive |

**Rules:**

- [ ] Every track starts at 0 and ends at the loop length with the **same value** (`keyed()` asserts it).
- [ ] Use `flow()` for continuous motion (smooth through keys and across the loop seam). Use `hold` only
      for pose and face switches.
- [ ] Keep beats long enough to read at 120 px: at least 1.5 s per beat.

## Step 7: Verify by looking

```powershell
python app\tool\mascot_rive_<rig>\build_<rig>.py
python app\tool\mascot_rive_<rig>\verify_<rig>.py --quick     # fast loop while iterating
python app\tool\mascot_rive_<rig>\verify_<rig>.py             # final: previews too
.\app\tool\preview_mascot_<rig>.ps1                           # live in the browser (VS Code browser works)
```

Update `beats` in the verifier to your story frames. Then check:

- [ ] `rive --verify`: 0 errors, 0 warnings; loop seam diff ≤ 3.
- [ ] `build/review.png`: every beat reads, with no seams, gaps, green rims, or parts floating off pivots.
- [ ] `build/chat_size.png`: still readable at the real UI size.
- [ ] Live preview: watch at least three full loops. Look for pops, hitches at the seam, arms that cut off
      at the shoulder, and bobbing that's too stiff or too floaty.
- [ ] Frame-to-frame diff: big spikes should only be the intended pose swaps.
- [ ] Capture blink/pose transitions and check every changed reusable segment's seam as well as the main loop.
- [ ] Nonempty `.riv` under 4,000,000 bytes; check the size explicitly.

The commands for a new `<rig>` are naming conventions to implement, not existing
generic scripts. Jack's verifier samples segments but does not test their seams
or enforce the size budget; neither mode performs a full frame-diff analysis.
Its `--quick` mode also skips the previews and small-size strip.
Run one verifier per rig at a time because segment capture temporarily edits `rive.yaml`.

Fix and repeat. Prefer timing fixes over new art; generate new art only when a pose truly can't be faked.

## Step 8: Deliver the standalone animation (default)

- [ ] Keep the accepted `.riv` and review artifacts in this rig's workshop `build/`.
- [ ] Write the rig README: approved story, look, palette, exact prompts, parts,
      pivots, artboards/state machines, tool versions, validation results and handoff.
- [ ] Document standalone preview commands and the static-poster plan.
- [ ] Review status/diff against the session baseline. No new Flutter runtime code,
      shipped assets, tests, platform config or pubspec changes.
- [ ] Commit/push only if requested; stage this task's files explicitly. Never
      commit tokens, login state, `send.js`/`fetch.js`, prompt dumps or scratch captures.
- [ ] **Stop here** unless Flutter integration is explicitly approved.

## Step 9: Integrate into Flutter (optional, separate approval)

- [ ] Copy the approved `.riv` to `app/assets/mascots/rive/` and keep a matching
      transparent PNG for web/reduced motion/failure. Preserve other assets.
- [ ] Add `MascotPose` entries (`file`, `riveArtboard`) and render with
      `AnimatedMascot(pose, animationAsset: ...)` (section 8 of the pipeline doc). Run `flutter analyze`
      and focused Flutter tests.
- [ ] Hot reload/restart a connected app; check native playback, web/reduced-motion
      posters, load failures and affected startup behavior. Report unavailable device checks.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Gemini didn't send, or nothing happens | Bring Chrome on screen; inspect page/response state before retrying to avoid duplicate sends |
| "You've reached your limit" | Pause or ask for an approved alternative provider; respect account quotas |
| Edit drifted (moved, resized or restyled) | Same chat: "That moved the X. Keep everything pixel-identical to the image I attached; only …" |
| Green rim around parts | `key()` already strips a 4 px rim; widen `MinFilter(9)` or lower `GREEN_LO_RIM` |
| Green details vanish (leaf, cherry stems) | Pass `keep_green` for that part, or cut it from its own render |
| Part pops when it rotates | The pivot is wrong, or the node origin isn't at the pivot; check against `master.png` |
| Arm cut off at the shoulder | Extend the arm layer under the sleeve/body, and draw it behind the body edge |
| Body shows a ghost head or shoulder | Cut the body alpha where the head layer covers it (`yy >= …`) |
| Loop hitch | A track's last value differs from frame 0, or uses `hold`/`linear` where it should `flow` |
| `rive --screenshot` shows the wrong artboard | The CLI renders `main:` from `rive.yaml` only; `verify` swaps it temporarily |
| VS Code shows a still `.webp` | Use the live preview script (it plays the real `.riv`) |
