# Start here

Next session, open this folder in Cursor or OpenCode and say:

```text
run 1-start
```

That skill interviews you. Bring an idea, or bring the interests you want it to turn into an idea. Scope, product requirements, and the technical plan come after that interview. This folder is ready for that conversation.

## What is already done

- The Devpost Learn skill pack is installed in `.agents/skills/` for Cursor and OpenCode.
- Hackathon notes are in this `hackathon/` folder.
- `LICENSE` is MIT so a public GitHub repo can show an open-source license in About.
- `.gitignore` already excludes `devpost/learner-profile.md` and local `.env` files.

## What this folder is

These notes are context for **this** hackathon project. There is no app yet. `devpost/scope.md`, `devpost/prd.md`, and `devpost/spec.md` are intentionally absent. The skills write those from your answers, and the judges use them as proof you followed the curriculum.

If `1-start` pauses because the folder looks occupied, tell it the `hackathon/` notes, `LICENSE`, and `README.md` are reference material for this project, and ask it to continue.

## The path

1. `1-start` — who you are, and any idea or interest you already have. Writes `devpost/learner-profile.md`.
2. `2-scope` — sharpen the idea until it fits an afternoon. Writes `devpost/scope.md`.
3. `3-prd` — how it looks, feels, and behaves. Writes `devpost/prd.md`.
4. `4-spec` — how it is built. Writes `devpost/spec.md`.
5. `5-build` — build and review it in slices. Writes the app, `devpost/checklist.md`, and `devpost/app-map.html`.
6. `6-ship` — demo video, public repo, and a submission you write yourself.

Say the next skill by name when you are ready. A fresh chat is fine. The files in `devpost/` carry the decisions forward.

A clear "looks good" approves a plan the skill has shown you. Silence does not.
