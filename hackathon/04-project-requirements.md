# Project requirements

Sources: hackathon overview (https://learn-ai-basics.devpost.com/) and Official Rules, section 4 (https://learn-ai-basics.devpost.com/rules).

## What to create

A **new** software project built with the Devpost Learn Skill Pack. It must be a working proof of concept that performs at least one function end to end.

Three checks called out on the hackathon site:

1. **New project.** Started from a folder set aside for this hackathon during the submission period (September 22, 2026, 10:00 am ET through October 26, 2026, 5:00 pm ET). An old idea is fine. Old code is not.
2. **Built with the skills.** Run them in Cursor or OpenCode. They are already installed here. Start with `run 1-start`.
3. **Planning docs in the repo.** The public repository must include `devpost/scope.md`, `devpost/prd.md`, and `devpost/spec.md` generated by the skills. Stage-one judging looks for those documents as evidence you used the skill pack.

Do not paste empty copies of those files in advance. The skills treat placeholder copies as non-progress and write them after you answer.

## Functionality and platforms

The project must install and run consistently on the platform you name, and it must work the way the video and description show. Standard tools are allowed: frameworks, libraries, starter templates, and AI coding assistants. Disclose any other pre-existing code or work you incorporate. The work you describe and submit must have been built during the submission period.

Third-party SDKs, APIs, and data are allowed only if you are authorized to use them under their terms.

This workspace is constrained to tools already available: **Node.js, Git, Cursor, and OpenCode**. Pick a stack inside that set when `4-spec` asks how to build. Do not add a new language runtime or a new application framework before that conversation.

## Size

Keep it proof-of-concept sized: one thing, end to end, finishable in an afternoon. The scope skill exists to cut a large idea down and to find an idea if you do not have one yet.

## What the repo must contain by submission

- Source, assets, and instructions needed for the project to function.
- The planning documents above, plus the checklist and app map the build skill produces.
- A public GitHub, GitLab, or Bitbucket repository.
- An open-source license file, visible at the top of the repository page (GitHub About). This repo already has an MIT `LICENSE`. Put your name on the copyright line before you publish if you want it named.
- Factual run instructions. `6-ship` checks those. It does not write your Devpost pitch.
